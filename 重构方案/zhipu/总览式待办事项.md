# 文档生成系统Store-Composable-View重构总览

## 项目概览

本文档是文档生成系统架构重构的总览式待办事项，基于对现有系统的深入分析，制定了从当前架构向Store-Composable-View三层架构转型的完整计划。

## 重构目标

### 主要目标

- [x] **架构清晰化**: 建立清晰的Store-Composable-View三层架构
- [x] **职责分离**: 确保Store只管状态，Composable处理业务逻辑，View只负责UI
- [x] **可维护性提升**: 降低代码复杂度，提高可测试性和可维护性
- [x] **渐进式迁移**: 确保重构过程中页面持续可用

### 成功指标

- [ ] 代码复杂度下降30%
- [ ] 组件复用率提升50%
- [ ] 测试覆盖率提升40%
- [ ] 新功能开发效率提升30%
- [ ] 性能下降控制在10%以内

## 当前系统分析

### 已完成的分析工作 ✅

#### 1. 数据流动过程分析

- **项目列表**: 项目管理 → 项目创建/编辑/删除 → 状态跟踪
- **选题策划**: 需求定义 → AI简报生成 → 标题生成 → 确认选题
- **大纲生成**: AI大纲生成 → 素材绑定 → 大纲编辑 → 保存大纲
- **内容创作**: 章节内容生成 → 内容编辑 → AI助手功能 → 文档保存

#### 2. 功能与服务映射

- **9个核心功能模块**: 项目管理、选题策划、大纲管理、内容创作、素材管理、任务管理、数据同步、用户认证、系统配置
- **45个具体功能点**: 详细的功能列表和对应服务映射
- **3层服务架构**: AI Services、Core Services、Business Services、Infrastructure Services

#### 3. 现有架构痛点

- **大型Composable**: `useTopicSelection.ts`(817行)、`useOutlinePage.ts`(1233行)
- **复杂状态管理**: 多个Store间状态同步复杂
- **职责混乱**: View层包含业务逻辑，Composable层直接操作DOM
- **测试困难**: 组件耦合度高，单元测试复杂

## 重构计划总览

### 阶段规划

```
准备阶段 (1-2天) → Store层重构 (3-5天) → Composable层重构 (5-7天) → View层重构 (4-6天) → 集成清理 (2-3天)
总计: 15-23天
```

### 核心策略

- **渐进式迁移**: 逐步替换，向后兼容
- **功能开关**: 控制新旧代码切换
- **适配器模式**: 处理接口差异
- **零停机**: 确保系统始终可用
