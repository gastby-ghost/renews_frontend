**新增功能（2025-11-08）**：解决AI服务与数据库后端协调问题的中间层服务

**需要关注的文件**：

#### 数据库同步服务

- `src/services/databaseSyncService.ts` - 数据库同步服务

- `src/services/enhancedTaskManager.ts` - 增强任务状态管理器
  - 统一管理所有AI任务的生命周期

  - 失败任务自动重试机制
  - 通知系统集成

#### 优化后的组合式函数

- `src/composables/document/useTopicSelection.ts` - 已优化集成数据库同步
  - 新增方法：`handleScopeTaskCompleted()`
  - 新增方法：`handleSearch2TitleTaskCompleted()`
  - 新增方法：`retryFailedTask()`

#### 示例组件

- `src/components/custom/document/optimized-topic-selection/OptimizedTopicSelection.vue`

  // 重试逻辑已集成到useTopicSelection中

**开发重点**：

- AI任务与数据库操作解耦
- 自动重试机制

### 状态管理操作

1. **定义State**

   ```typescript
   const materials = ref<Material[]>([])
   const loading = ref(false)
   ```

2. **定义Actions**

   ```typescript
   const fetchMaterials = async () => {
     loading.value = true
     try {
       const result = await materialService.getList()
       materials.value = result.data
     } finally {
       loading.value = false
     }
   }
   ```

3. **返回响应式数据**
   ```typescript
   return {
     materials,
     loading,
     fetchMaterials
   }
   ```

## 核心开发原则

### 1. 📐 分层架构

**原则**：每层只关注自己的职责

- **表示层**（Views/Components）→ UI展示、用户交互
- **业务逻辑层**（Composables/Store）→ 业务规则、数据处理
- **服务层**（Services）→ API调用、数据获取
- **基础设施层**（Utils/Types）→ 工具、类型、配置

**实践**：

- 组件不直接调用API
- 服务不直接操作DOM
- 状态变化可预测

---

### 2. 🔄 单向数据流

```
用户操作 → 组件事件 → Composable → Store Action → API服务 → 更新状态 → UI响应
```

**实践**：

- 状态只能通过Store action修改
- 组件通过computed响应状态变化
- 避免直接修改store状态

### 4.2. 🔄 异步任务处理最佳实践（素材绑定示例）

**新增功能（2025-11-11）**：基于素材绑定功能，展示异步任务处理的标准模式

#### 异步任务模式概述

现代AI服务普遍采用**异步任务模式**：
1. **创建任务**：POST请求创建异步任务，立即返回task_id
2. **轮询状态**：通过GET请求轮询任务状态（status, progress）
3. **获取结果**：任务完成后获取最终结果
4. **错误处理**：处理失败、超时等异常情况

#### 标准实现架构

```
用户操作
   ↓
创建任务 (API: POST /xxx/execute)
   ↓
启动轮询 (AsyncTaskPoller)
   ↓
查询状态 (API: GET /xxx/status/{task_id})
   ↓
更新UI (实时显示progress)
   ↓
任务完成 → 处理结果 → 更新状态 → 用户反馈
   ↓
任务失败 → 错误处理 → 显示错误 → 提供重试
```

#### 核心组件

**1. 服务层 (`src/services/documentGenerateService.ts`)**
